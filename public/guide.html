Gate guide

Four stores, four admission rules

Agent memory is a read-and-write system. Retrieval searches the three long-term stores; the write path decides what earns a place in them — and each store answers a different question.

Simulation, honest limits. The stores and gates are policy models — no model calls, no embeddings. "Confirmed" and "worked" arrive as transcript metadata; a real system has to infer them.

Start here

What this demo proves

One transcript, two write policies. Write-naive admits every candidate as a durable fact: a hedged "I might prefer aisle" becomes permanent on episode one, both stale prices ($312 and $404) coexist as facts, and a UI spinner trace lands in knowledge. The gated policy drops the transient, parks the unconfirmed claim in pending until it repeats in a second episode, and promotes the rule only after it proves out twice. Same transcript — the difference is entirely on the write path.

The stores

What each store accepts

Store 1

Working

Scratch for the current turn — the request, tool output, this episode's state. Writes freely, evicts at episode end.

Gate
None on write; the discipline is that it is never searched — retrieval is for the three long-term stores.
Store 2

Episodic

What happened: "Trip booked: AUS → JFK, 8:40 AM, aisle 14C." An episode is a unit with an ending.

Gate
Only a completed episode writes. Mid-episode fragments — a spinner, a partial result — are dropped.
Store 3

Semantic

Durable facts: "prefers aisle seat", "flights before 10 AM". The store that answers "what is true about this user/world?"

Gate
Confirmed in-session → durable. Stated once → pending; it promotes only if repeated in a different episode or explicitly confirmed. Transient truths (today's price) are dropped outright.
Store 4

Procedural

Rules that earned it: "always check the 14-day advance-purchase window". Skills and policies, not observations.

Gate
A rule candidate must prove out in minSuccesses distinct episodes (2 here) before it becomes recallable procedure — one lucky run is an anecdote, not a skill.

The failure

Write-naive = memory pollution

The naive mode models the default "log everything to the vector store" design: every candidate — hedged preference, hourly price, UI trace, one-off rule — becomes a durable fact in one blob. Retrieval still works (keyword overlap stands in for semantic search), so the pollution surfaces with full confidence: the follow-up request pulls back both stale prices and a preference that was never confirmed. Month-three recall bugs are month-one write bugs.

Limits

What this demo does not claim

  • Simulated stores — no vector DB, no embeddings; retrieval is keyword overlap standing in for semantic search.
  • "Confirmed", "transient", and "worked" are transcript metadata; a real agent must infer them — that inference is the hard part this lab abstracts away.
  • The gates here are minimal admission rules, not a full lifecycle: no decay, compaction, conflict resolution, or human review queue.
  • Thresholds (2 observations, 2 proofs) are illustrative — real values depend on blast radius.
